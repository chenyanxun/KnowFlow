# KnowFlow 第一期计划

**目标：** 做一个单一客户使用的内部后管。用来练习企业级后管的常见做法：登录、权限、菜单，以及带上传的文档管理。

**范围：** 只做第一期。C 端、AI 问答、多租户先不写。

**做法：** 后端用 NestJS 自己写，包括模块划分、数据表、接口和权限判断。前端用 React，页面可以让 AI 按下面的行为来做。数据表字段和接口路径不在本文规定。

## 技术栈

| 层 | 选择 |
|---|---|
| 管理端 | React + Vite + TypeScript |
| 接口 | NestJS + TypeScript |
| 数据库 | MySQL 8 |
| ORM | TypeORM |
| 登录态 | JWT |
| 文件 | 保存在服务器本地目录，数据库只记录文件信息 |

业务规则放在 NestJS。React 只做页面和调用接口。

仓库先放两个应用：`apps/api`、`apps/admin`。本地用 Docker 启动 MySQL。

## 功能

| 功能 | 行为 |
|---|---|
| 登录 | 账号密码登录、退出。登录后拿到当前用户和他能看到的菜单 |
| 仪表盘 | 看到账号数量、文档数量、今日上传数量，以及最近上传的文档 |
| 菜单管理 | 维护一棵菜单树。菜单可以是目录、页面或按钮 |
| 角色管理 | 维护角色，并给角色勾选能使用的菜单 |
| 账号管理 | 创建和编辑账号，分配角色，重置密码，启用或停用 |
| 文档管理 | 查看列表，上传、下载、删除文件 |

账号在「账号管理」里创建，本期不做公开注册。库里还没有账号时，种子数据放进一个超级管理员，用来第一次登录。

## 权限怎么理解

侧边栏从菜单数据渲染，不在前端写死。

目录只用来分组。页面对应一个管理端画面。按钮表示页面上的操作，例如上传、删除。角色决定能看到哪些菜单、能点哪些按钮。一个账号可以有多个角色，能看到的菜单是这些角色的合集。

超级管理员使用全部功能。这个角色不能删，系统里至少留一个这样的账号。

停用的账号不能再登录，已经登录的也会失效。

删菜单时，下面还有子菜单就先不让删。删角色时，还有账号在用就先不让删。

## 文档上传

上传前检查大小和类型，不合适的文件直接拒绝，不写入磁盘，也不记入数据库。

保存时使用服务端生成的文件名，避免重名和路径问题。下载通过后端读出文件。删除时，数据库记录和磁盘文件一起去掉。

## 完成时能演示什么

- 超级管理员登录后能看到全部菜单，并完成六个功能。
- 新建一个只能访问文档管理的角色和账号。这个账号看不到账号管理，也不能操作别人的账号。
- 取消某个角色的上传能力后，对应账号仍能打开文档列表，但不能上传。
- 停用账号后，该账号不能继续使用系统。
- 上传成功后列表里看得到，下载下来的内容和原文件一致。删除后列表和磁盘上都没有了。

## 建议顺序

先后端，再前端。每完成一块后端，就可以让 AI 做对应页面。

1. 搭好 NestJS、React 和 MySQL。
2. 登录，以及当前用户能看到的菜单。
3. 菜单管理。
4. 角色管理，把角色和菜单关联起来。
5. 账号管理，把账号和角色关联起来。
6. 仪表盘。
7. 文档的上传、列表、下载和删除。
